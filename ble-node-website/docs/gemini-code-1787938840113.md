# Web Client Architecture & Algorithm (PWA Scanner)

Dokumen ini menjelaskan arsitektur *frontend* berbasis peramban (Chrome Android) yang bertugas memindai sinyal *Bluetooth Low Energy* (BLE) secara pasif, mengekstrak nilai RSSI, dan menghitung estimasi jarak ke *node*.

## 1. Arsitektur Sistem Web

Karena ini berjalan di atas peramban tanpa instalasi aplikasi *native*, arsitektur berpusat pada antarmuka **Web Bluetooth API** (khususnya fitur *scanning*, bukan GATT *pairing*).

*   **User Interface (UI) Layer:** Halaman HTML/CSS sederhana dengan tombol pemicu mutlak (misal: "Mulai Navigasi"). Tombol ini wajib ada untuk melewati sistem keamanan peramban.
*   **Web Bluetooth Engine:** Menjalankan perintah `navigator.bluetooth.requestLEScan()`. Komponen ini bekerja di latar depan dan mengharuskan layar perangkat tetap menyala.
*   **Event Pipeline:** *Listener* `advertisementreceived` yang menangkap setiap paket BLE yang lewat. Pipeline ini mengekstrak dua data utama: `device.id` (atau *MAC Address*) dan `rssi`.
*   **Data Processing Layer:** Mengubah nilai RSSI mentah yang sangat fluktuatif menjadi jarak estimasi (meter), lalu memperbarui status posisi pada layar (UI Update) setiap 100-500 milidetik.

## 2. Alur Logika (State Machine)

1. **State `IDLE`:** Web dimuat, peta statis ditampilkan. Menunggu interaksi pengguna.
2. **State `REQUEST_PERMISSION`:** Pengguna menekan tombol. Web meminta izin lokasi dan Bluetooth ke OS Android.
3. **State `SCANNING_LOOP`:** 
   - Web mendengarkan paket BLE di udara.
   - Setiap paket masuk, data masuk ke *Buffer Array* berdasarkan ID Node.
4. **State `CALCULATING`:** Setiap *N* milidetik, fungsi kalkulasi dijalankan untuk menghitung rata-rata RSSI dan mengubahnya menjadi jarak.
5. **State `UI_UPDATE`:** Memperbarui teks/grafik di layar, lalu kembali ke `SCANNING_LOOP`.

## 3. Algoritma Inti

### A. Algoritma Penghalus Data (Smoothing)
Sinyal RSSI mentah sangat berisik karena pantulan dinding (*multipath fading*). Tidak bisa langsung dipakai untuk kalkulasi. PoC ini menggunakan algoritma **Exponential Moving Average (EMA)**:

$$EMA_{current} = (\alpha \times RSSI_{raw}) + ((1 - \alpha) \times EMA_{previous})$$

*Nilai $\alpha$ (alpha) adalah faktor pembobotan antara 0 dan 1 (biasanya 0.2 untuk meredam lonjakan ekstrem).*

### B. Algoritma Estimasi Jarak (Log-Distance Path Loss)
Setelah RSSI dihaluskan, ubah menjadi estimasi jarak fisik menggunakan rumus propagasi sinyal:

$$d = 10^{\frac{TxPower - RSSI}{10n}}$$

*   **$d$:** Jarak dalam meter.
*   **$TxPower$:** Nilai kalibrasi RSSI pada jarak tepat 1 meter (biasanya sekitar -59 hingga -65 dBm).
*   **$RSSI$:** Nilai RSSI yang sudah dihaluskan dari algoritma EMA.
*   **$n$:** Faktor redaman lingkungan (sekitar 2.0 untuk ruang terbuka, 3.0 - 4.5 untuk dalam ruangan dengan banyak dinding).

Untuk tahap PoC, web cukup menampilkan tabel berisi ID perangkat, nilai RSSI mentah, nilai RSSI halus, dan estimasi jarak (meter) yang terus berganti secara *real-time*.
