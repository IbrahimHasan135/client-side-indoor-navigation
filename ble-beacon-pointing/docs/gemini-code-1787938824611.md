# ESP32 Beacon Architecture & Firmware

Dokumen ini menjelaskan rancangan *firmware* untuk *node* pemancar (Anchor). Tujuannya sangat spesifik: mengubah mikrokontroler menjadi suar (*beacon*) pasif yang menyiarkan identitasnya tanpa henti.

## 1. Arsitektur Perangkat Keras & Firmware

Target arsitektur menggunakan keluarga *chip* modern (seperti ESP32-S3 atau ESP32-C6) dengan pengembangan berbasis **ESP-IDF** atau **PlatformIO (Arduino Framework)**. 

*   **Layer Perangkat Keras:** Modul radio Bluetooth 5 (BLE) internal pada ESP32. Antena PCB bawaan (atau antena eksternal untuk radius lebih stabil).
*   **Layer Protokol (GAP - Generic Access Profile):** *Firmware* berjalan murni sebagai **Broadcaster**. Modul GATT (untuk *pairing* dan transfer data dua arah) dimatikan total untuk menghemat memori dan mempercepat siklus pancaran.
*   **Format Paket:** Menggunakan format standar industri (seperti Apple iBeacon atau Google Eddystone-UID) agar paket mudah dikenali oleh API peramban standar tanpa harus melakukan dekode *payload* khusus.

## 2. Alur Logika (Firmware Flow)

Karena tidak ada sensor atau pemrosesan logika berat, siklus *firmware* sangat linear:

1. **Inisialisasi Sistem:** 
   - Booting, mematikan modul Wi-Fi secara eksplisit (hanya butuh BLE).
   - Inisialisasi *Bluetooth Controller* dan Bluedroid/NimBLE *stack*.
2. **Konstruksi Paket Advertising (Payload):**
   - Mengatur parameter dasar paket BLE.
   - Menetapkan UUID unik untuk membedakan *node* ini dengan *node* gedung lain.
   - Menetapkan Major/Minor ID (misal: Lantai 1, Node 3).
3. **Konfigurasi Radio (Tx Power):**
   - Menetapkan daya pancar. Pada ESP32, diatur ke tingkat maksimal (misal: `ESP_PWR_LVL_P9` atau +9 dBm) untuk menembus halangan dalam ruangan.
4. **Looping Transmisi (Advertising Loop):**
   - Menjalankan perintah mulai siaran (`esp_ble_gap_start_advertising`).
   - Mikrokontroler dibiarkan beroperasi tanpa melakukan apa-apa di fungsi `loop()` utama, sistem operasi internal (RTOS) yang mengambil alih penyiaran radio secara otomatis di latar belakang.

## 3. Algoritma dan Parameter Konfigurasi

Untuk memastikan stabilitas tangkapan data di sisi peramban web, pengaturan interval waktu (*Advertising Interval*) sangat krusial. 

*   **Advertising Interval (T_adv):** Waktu jeda antara setiap pancaran paket.
    *   *Nilai PoC Optimal:* 100 milidetik (0.1 detik).
    *   *Logika:* Interval yang sangat rapat memastikan peramban web mendapatkan banyak sampel data RSSI dalam 1 detik. Ini membuat algoritma *Moving Average* di *frontend* bekerja jauh lebih presisi untuk membuang sinyal palsu.
*   **Daya Pancar vs Konsumsi Arus:** 
    *   Karena interval disetel sangat rapat (100ms), ESP32 tidak bisa masuk ke mode *Deep Sleep* dengan efisien. 
    *   Arsitektur PoC mengasumsikan *node* dicolokkan ke listrik dinding konstan (Adaptor 5V) alih-alih baterai koin. 

Penerapan *firmware* ini cukup di-*flash* ke dalam perangkat, dan ESP32 akan langsung menjadi *blind broadcaster*—hanya berteriak memancarkan koordinat sinyalnya ke udara agar bisa ditangkap oleh jaring peramban.
